## 1. החזון
מרקטפלייס פתוח שבו **כל אדם עם מומחיות** – טכנאי מחשבים, אינסטלטור, סוכנת נסיעות, מורה פרטי, סטודנט שמרכיב רהיטים –
נרשם בדקה, רואה קריאות פתוחות ומרוויח כסף. הלקוח לא מחפש ולא מתקשר ל-10 מספרים: הוא פותח קריאה קצרה ומקבל הצעות.

**הכל מהכל**: שליח שיביא אוכל, מסירה משפטית של כתב תביעה, הוצאת כלב, צלם לאירוע, טכנאי מחשבים מרחוק, חופשה ביוון.
אם אדם יכול לעשות את זה בשביל אדם אחר – יש לזה קטגוריה (ואם אין – "אחר – כל מומחיות").

שלושה סוגי "סחורה" באותה פלטפורמה:
| סוג | דוגמה | איך מרוויחים |
|---|---|---|
| **שירות** (אצל הלקוח / מרחוק / בטלפון) | תיקון מחשב, ריצוף, ייעוץ משפטי | עמלה על שליחת הצעה + עמלת הצלחה בתשלום באפליקציה |

## 1ב. איסוף ומשלוח – "Uber לשליחויות" ✅
- הלקוח: "מאיפה לאסוף" (מסעדה/חנות/משרד עו"ד) + "לאן להביא" (ריק = המיקום שלי) + "השליח קונה עבורך? כמה זה עולה".
- הקריאה נשלחת לשליחים **ליד נקודת האיסוף**. בפיד: מרחק לאיסוף, אורך המסלול, סכום הקנייה.
- שלבים: יצאתי לאיסוף → אספתי → נמסר (תמונה כהוכחה). ניווט Waze לאיסוף ולמסירה.
- **"קנה עבורי"**: בתשלום באפליקציה הלקוח משלם דמי משלוח + עלות הקנייה; השליח מקבל את עלות הקנייה **בחזרה במלואה, בלי עמלה**, והעמלה רק על דמי המשלוח.
- **מסירה משפטית** היא קריאת משלוח: איסוף מסמכים ממשרד עו"ד → מסירה לנמען → תמונה. 🔜 תבנית תצהיר מוסר שהשליח ממלא וחותם.
- 🔜 מעקב חי על מפה, הוכחת מסירה עם חתימה דיגיטלית, משלוחים מרובים למסלול אחד, שליחים קבועים לעסקים (B2B).
- ⚠️ לבדוק: ביטוח לרכב/אופנוע לשליחים, איסוף תרופות מרשם (ייפוי כוח), איסור משלוח אלכוהול לקטינים.

## 3. הרשמה מהירה – "כל מי שזז על הרגליים"
המטרה: **מאדם בלי עבודה ועד הצעה ראשונה – פחות מ-3 דקות.**

1. ✅ שם + טלפון → קוד SMS → בפנים. אין סיסמה, אין טפסים ארוכים.
2. ✅ **30 ₪ קרדיט מתנה** – אפשר לשלוח 2–3 הצעות ראשונות בלי להוציא שקל.
3. ✅ בחירת תחומים בצ'יפים. תחומים **ירוקים = "מתחילים היום"** (בלי רישיון): הרכבת רהיטים, הנדימן, סבלות, גינון, שליחויות, ניקיון, שיעורים, "אחר – כל מומחיות".
4. ✅ איפה אני עובד: אצל הלקוח (רדיוס) / מרחוק / בטלפון. מרחוק = לקוחות מכל הארץ.
5. ✅ מתג "פנוי לקריאות" → הפיד מתמלא.
6. ✅ **תוכנית חבר מביא חבר**: קישור אישי, 25 ₪ קרדיט למזמין – רק אחרי שהחבר **סיים עבודה ראשונה** (מונע הונאות).

## 6. נסיעות ומלאי ספקים (RateHawk ודומיו)
### 6.1 המודל
הפלטפורמה מחזיקה את החוזים מול הספקים. סוכן (גם סוכן עצמאי מהבית) מקבל קריאה "מלון באתונה לזוג",
מחפש במלאי, מוסיף **את הרווח שלו**, ושולח הצעה. הלקוח משלם באפליקציה, המערכת מזמינה אצל הספק.

```
מחיר ללקוח = מחיר נטו של הספק (בש"ח) + תוספת פלטפורמה + תוספת הסוכן
```
| רכיב | ברירת מחדל | הערה |
|---|---|---|
| תוספת פלטפורמה – מלונות | 8% | ✅ ניתן להגדרה |
| תוספת פלטפורמה – טיסות | 4% | ✅ מרווחים נמוכים בטיסות |
| תוספת פלטפורמה – אטרקציות/מוצרים | 10% | ✅ |
| עמלה על תוספת הסוכן | 12% | ✅ הסוכן מקבל 88% מהרווח שלו |
| מרווח מט"ח | 2% | ✅ הגנה מתנודות שער |

✅ הסוכן רואה רק **מחיר בסיס** (נטו + תוספת פלטפורמה) – לעולם לא את הנטו של הספק.
✅ המחיר מחושב מחדש בשרת מהספק – מחיר שנשלח מהדפדפן מתעלמים ממנו.

### 6.2 ספקים
| ספק | מה | מצב |
|---|---|---|
| **RateHawk / ETG API v3** | מלונות במחירי B2B | ✅ מתאם כתוב (חיפוש אזור → prebook → booking form → finish → status). **חובה לאמת מול sandbox.** |
| **Duffel** | טיסות | ✅ מתאם כתוב (offer request → offer → order). **חובה לאמת במצב test.** |
| **ה-API שלנו לספקים** | צימרים, מלונות מקומיים, אטרקציות, חנויות | ✅ ראו 6.4 |
| Amadeus / Kiwi / Hotelbeds / Expedia Rapid | חלופות/השלמות | 🔜 |

### 6.3 הזמנה
1. ✅ הלקוח בוחר הצעה → **בדיקת מחיר מחדש מול הספק** (סטייה מעל 2% = חסימה + בקשה מהסוכן להצעה מעודכנת).
2. 🔜 חיוב כרטיס הלקוח (ספק סליקה) – **לפני** ההזמנה אצל הספק.
3. ✅ הזמנה אצל הספק → מספר אישור → נרשם בתיעוד.
4. ✅ כשל → הכסף מוחזר. כשל חלקי (טיסה אושרה, מלון לא) → מסומן לתמיכה.
5. 🔜 שובר במייל/וואטסאפ, תזכורת לפני הטיסה.
6. 🔜 **תשלום לסוכן רק אחרי הצ'ק-אין / ההמראה** – לא ברגע ההזמנה (בגלל ביטולים).
7. 🔜 ביטולים לפי מדיניות הספק (`free_cancellation_before`), החזר חלקי, דמי ביטול.

### 6.4 API לספקים – "ה-RateHawk של הפלטפורמה" ✅
חברות מפרסמות מלאי במחיר נטו, וכל סוכן/מקצוען יכול למכור אותו.
- אדמין יוצר ספק → מקבל **מפתח API** (מוצג פעם אחת, נשמר כ-hash).
- `POST /api/partner/v1/products` – `kind` (hotel/flight/activity/product), `title`, `netPrice`, `currency`, `stock`, `location`, תאריכים.
- `PUT` / `DELETE` מוצר, `GET /api/partner/v1/bookings` – הזמנות + פרטי לקוח + הסכום שמגיע לספק.
- ✅ מלאי יורד בכל הזמנה; מוצר שאזל לא מופיע בחיפוש.
- 🔜 Webhook חתום לספק על הזמנה חדשה, לוח זמינות לפי תאריכים, פורטל ספקים, התחשבנות חודשית אוטומטית.

### 6.5 "מכר משהו" – מוצרים
אותו מנגנון: ספק מפרסם מוצר (`kind: product`), טכנאי מוסיף ראוטר להצעת התיקון, מתקין מזגנים מוסיף מזגן.
✅ פריטי קטלוג רק בתשלום באפליקציה (הכסף לספק עובר דרכנו).
🔜 שלב 2: לוח מודעות יד-2 (מכירה בין אנשים), משלוחים, החזרות.

- מספרים מוסווים (Call masking) – שיחות עוברות דרך מספר וירטואלי: מונע זליגה מהפלטפורמה ומתעד.
- דיווח וחסימה, ניטור תוכן בצ'אט, זיהוי חשבונות כפולים/מזויפים.
- **מחלוקות**: התיעוד (תמונות לפני/אחרי, חתימה) + צ'אט = ראיות. אדמין מכריע: שחרור / החזר / חלוקה.
- **שחרור אוטומטי**: אם הלקוח לא אישר ולא פתח מחלוקת תוך 72 שעות – הכסף משתחרר למקצוען.
- ביטוח אחריות מקצועית לפלטפורמה; ביטוח צד ג' חובה בשיפוצים (✅ כדרישת מסמך).

## 10. עלייה לאוויר (Go-to-market)
- **ביצה ותרנגולת**: מתחילים **בעיר אחת + 3–4 תחומים** (למשל באר שבע: מחשבים, הנדימן, ניקיון, נסיעות מרחוק לכל הארץ).
- היצע קודם: גיוס מקצוענים בקבוצות פייסבוק/וואטסאפ, לשכות תעסוקה, מכללות – "30 ₪ מתנה + חבר מביא חבר".
- ביקוש: דפי נחיתה ל-SEO לכל תחום+עיר ("טכנאי מחשבים בבאר שבע") – בדיוק המקום שבו אנשים מחפשים בגוגל.
- שיתופי פעולה: ועדי בית, חברות ניהול נכסים, סוכנויות ביטוח (B2B).

## 11. מדדים (KPIs)
זמן עד הצעה ראשונה (יעד < 15 דק'), % קריאות עם 3+ הצעות, המרה קריאה→עבודה, Take rate, הכנסה לקריאה,
שימור מקצוענים (30/90 יום), % מקצוענים חדשים שסגרו עבודה ראשונה בשבוע, NPS, מחלוקות לכל 100 עבודות.

## 12א. איך זה רץ היום ✅
- **שרת**: Node.js, נתונים נשמרים לקובץ JSON בדיסק (נטען מחדש באתחול), `/healthz`.
  העלאה בלחיצה ל-Render (`render.yaml`) או כל שרת Docker (`backend/Dockerfile`).
- **SMS**: Twilio (משתני סביבה). בלי SMS השרת במצב הדגמה – הקוד מוצג על המסך.
- **APK**: שתי אפליקציות אנדרואיד מאותו קוד – `ProMarket` (לקוח, כתום) ו-`ProMarket למקצוענים` (כחול).
  כרגע הן "מעטפת" סביב אתר הווב (WebView) עם הרשאת מיקום, חייגן, Waze, בחירת תמונות, חזרה ומשיכה לרענון –
  כך כל פיצ'ר שנבנה בשרת זמין מיד באפליקציה. GitHub Actions בונה APK חתום בכל שינוי ומפרסם ב-Releases.
- 🔜 לפני חנות Google Play: מפתח חתימה פרטי, התראות Push (FCM), אייקונים ומסכי חנות, מדיניות פרטיות, החלפת מסכים לנייטיב לפי הצורך.

## 13. סדר עבודה מומלץ
1. **לאוויר**: העלאה ל-Render, חיבור Twilio, `SERVER_URL` ל-APK, בדיקות עם 10–20 משתמשים אמיתיים בעיר אחת.
2. **בסיס לפרודקשן**: Postgres/PostGIS, ספק סליקה עם פיצול, העלאת קבצים, Push.
3. **אמון**: צ'אט + מספרים מוסווים, מחלוקות, שחרור אוטומטי, החזר לידים, KYC.
4. **אפליקציות**: אנדרואיד מלא למקצוען (Onboarding, מפה, עבודות פעילות, ארנק, קטלוג), אפליקציית לקוח.
5. **נסיעות לאוויר**: אימות RateHawk/Duffel ב-sandbox, שוברים, ביטולים, תשלום לסוכן אחרי צ'ק-אין.
6. **ספקים**: פורטל + Webhooks + התחשבנות.
7. **צמיחה**: SEO, מנוי Pro, B2B, iOS.
